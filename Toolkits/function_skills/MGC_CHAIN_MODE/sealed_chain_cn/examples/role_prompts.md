# 角色与任务模板汇总

> 本文件是 chain mode 协作的**任务书模板库**。编排 agent 按场景复制对应模板、替换 `<>` 占位符后发给各 agent。
> 角色不是固定的，按**数据域**增减：每个数据域一个执行 agent，编排 agent 只有一个。
> 模板清单：模板 1 编排任务书 / 模板 2 分发指令 / 模板 3 执行任务书 / 模板 4 结果回传 / 模板 5 编排接收回传。

## 角色总览

| 角色 | 数量 | 持有数据/凭证 | 主要职责 | 产物 |
|------|------|:---:|---------|------|
| 编排 agent | 1 | ❌ 不持有 | 拆分任务、生成规格、分发、汇总 | 任务书、targets 规格、汇总报告 |
| 内部执行 agent | 每个内部数据域 1 个 | ✅ 只在本地 | 在本地数据域内执行脚本 | 结果摘要 |
| 外部执行 agent | 每个外部数据域 1 个 | ✅ 只在本地 | 在外部数据域内执行脚本 | 结果摘要 |

> 内部/外部是**数据边界**，不是设备。单数据域场景可以只有"1 编排 + 1 内部执行"，外部执行省略。

## 模板 1：编排 agent 任务书

```text
【角色】你是本次多 agent 加密协作的编排方。

【任务目标】
用 MGC chain mode 把任务 <任务名称> 拆成 <N> 个独立密封子包，分发给下列数据域：
- <数据域 1>（内部）：<该域负责的分析/处理内容>
- <数据域 2>（外部）：<该域负责的分析/处理内容>

【硬约束】
1. 你不接触任何业务数据与凭证。它们只存在于各执行方本地，由执行方自行准备。
2. 你只处理脚本文件（.py），不下发 CSV/JSON/config 等数据文件。
3. 工作流目录必须平级（无子目录），跨脚本 import 只能写 `from helper import ...`。
4. 子包内文件以授予清单为准，不授予的文件不会出现在对方环境中。
5. 每个子包交付前校验 sha256，校验值以 distribution_index.json 为准。

【交付物】
1. 工作流脚本目录（平级）
2. targets 规格 JSON（每项含 node_pub + files，files 只含 .py）
3. N 个密封子包 + distribution_index.json
4. 分发说明（传输方式、收件人、校验方式）
```

## 模板 2：编排 agent 分发指令

```text
【任务】为已存入 MGC 的工作流生成 chain mode 子包并分发。

【已存入】
info_owner = <owner>
diff_2      = <folder>

【数据域与授权文件】
- <数据域 1>：files = ["<script_a.py>", "<shared_helper.py>"]
- <数据域 2>：files = ["<script_b.py>", "<shared_helper.py>"]

【做法】
1. 向每个执行方索取 node_pub（对方在自己机器上执行 mgc_get 获取，多行 PEM 原样使用）。
2. 生成 targets，写成本地 JSON 文件，用 ext04="@<绝对路径>" 传入。
3. 调用 mgc_seal_package 产出子包。
4. 读取 distribution_index.json，按 node_pub_fingerprint 与节点指纹账本（各执行方的 email + node_pub + fingerprint）逐一核对收件人。
5. 默认用邮件分发：每个 task_package_NN/ 目录独立打包，附 sha256 校验值。
   - Subject 统一使用 `chain:<task_id>`，便于执行方按 keyword 做收件轮询过滤。
   - 每个附件的 sha256 写在邮件正文（不要只写在文件名里），供接收方导入前核验。
6. 分发完成后，等待各执行方回传结果，再做汇总。

【禁止】
- 不得把数据文件加入 files。
- 不得把多个子包合并成一个包发送。
- 不得在邮件正文贴 .mgc_file 的 base64（必须作为附件）。
```

## 模板 3：执行 agent 任务书

```text
【角色】你是本次任务中负责 <数据域名称> 的执行方。

【你的环境】
- 本机已运行 MGC（≥1.6.0）。
- 本域的数据/凭证已存入本机 MGC（info_owner=<本地 owner>），不向外传输。

【任务】
1. 接收编排方发来的 <task_package_NN>.mgc_file（邮件附件，Subject 含 `chain:<task_id>`）。
2. 校验：附件实际 sha256 与邮件正文中的值一致，再导入。
3. 导入：mgc_save_file(path="<本地路径>", info_owner="<包内 owner>", diff_2="<包内 diff_2>")。
4. 核对授权清单：mgc_find 确认实际拿到的文件与任务书列出的完全一致；若不一致，停止执行并回传异常。
5. 冒烟验证：注意"导入成功 ≠ 可解封"——解封发生在运行期。核对清单后先用小参数试跑入口脚本，若报 UNSEAL_FAILED（Double-layer unseal failed），说明子包与本机 node_pub 不匹配，停止并回传异常。
6. 正式执行：mgc_run(info_type="script", info_owner=..., diff_2=..., diff_3="<script.py>")。
   - 脚本内如需数据/凭证，从本机 MGC REST API 读取，不要写入磁盘、不要打印。
   - 若通过 ext02 传 --output 写文件，先确保父目录存在（密封脚本不会自动 mkdir）。
7. 结果只保留摘要：字段、指标、结论，不含原始数据行。

【硬约束】
- 不读取未授权的 MGC 记录。
- 不把数据/凭证写入结果或日志。
- 不修改密封脚本内容。
- 执行失败时回传错误摘要（错误类型 + 关键堆栈行），不回传环境变量。

【交付物】
一份结果摘要（JSON 或短文本），按模板 4 回传。
```

## 模板 4：结果回传

```text
【任务】回传 <数据域名称> 的执行结果。

【回传内容】
- 任务标识：<任务名称>
- 执行状态：success / failed
- 结果摘要：<结构化摘要，不含原始数据>
- 产物校验：sha256 = <值>
- 异常说明（仅 failed）：<错误类型 + 关键信息>

【回传方式】
- 方式 A（推荐，加密）：把结果封进 <report.py>（结果作为字符串常量），用编排方 node_pub 做 p2p 密封后回传。
- 方式 B（简单，明文）：直接把摘要写在邮件正文——仅在结果不含敏感信息时使用。

【禁止】
- 不得回传原始数据行、凭证、完整日志。
- 不得把结果与脚本混在同一个子包里回传。
```

## 模板 5：编排 agent 接收回传

```text
【角色】你是本次多 agent 加密协作的编排方，负责接收各执行方的回传结果。

【接收流程】
1. 按节点指纹账本核对回传来件：发件方 email ↔ 账本中登记的指纹，确认来源可信。
2. 校验：附件实际 sha256 与邮件正文中的值一致。
3. 导入：mgc_save_file(path="<回传包路径>", info_owner="<回传包内 owner>", diff_2="<包内 diff_2>")。
   回传包以编排方 node_pub 做 p2p 密封，只有编排方本机可解。
4. 运行：mgc_run(info_type="script", info_owner="<回传包内 owner>", diff_3="<report.py>")，
   结果由 report.py 写到外部（--output 或摘要落盘）。
5. 汇总：各数据域结果齐全后产出最终交付物。

【异常处理】
- sha256 不一致 / 来源指纹不匹配 → 拒收，要求执行方重发。
- 回传包导入失败 → 检查是否保持了 .mgc_file 后缀。
- 运行报 UNSEAL_FAILED → 回传包未用编排方 node_pub 密封，退回重封。

【禁止】
- 不得在回传链路中要求执行方附带原始数据或凭证。
- 不得合并多个执行方的回传包一起导入。
```

---

## 使用说明

1. **只复制需要的模板**，不要整份发给 agent。
2. 执行 agent 数量按数据域决定；只有一个数据域时省略模板 3 中"外部"相关描述。
3. 模板中的"禁止"条款是防止越权读取和二次泄露的关键，不要删减。
4. 任务书里的文件授权清单必须与 targets 的 `files` 字段逐项一致。
