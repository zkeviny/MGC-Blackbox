# 多 Agent 任务流模板

> 填空式模板。把 `<>` 替换成你的场景内容，即可得到一条 chain mode 协作流程。
> 原则：**数据与凭证不出域，只流转任务书、脚本、结果摘要。**

## 一、场景定义

| 项目 | 填写 |
|------|------|
| 任务名称 | `<例如：Q3 竞争分析>` |
| 目标 | `<一句话说明最终要产出什么>` |
| 编排方 | `<节点名称 / agent 名称>` |
| 数据域清单 | `<内部数据域：...>`、`<外部数据域：...>` |
| 最终交付物 | `<报告 / 数据集 / 决策建议>` |

## 二、角色与数据域

| 角色 | 所属数据域 | 本地数据/凭证 | 拿到的脚本 | 产物 |
|------|-----------|-------------|-----------|------|
| 编排 agent | — | 无 | — | 任务书 + 规格 + 汇总 |
| 内部执行 agent | `<内部域>` | `<本地 MGC owner：...>` | `<a.py, helper.py>` | `<结果摘要>` |
| 外部执行 agent | `<外部域>` | `<本地 MGC owner：...>` | `<b.py, helper.py>` | `<结果摘要>` |

> 只有一个数据域时删除"外部执行 agent"行。数据域多于两个时按同样格式增加行。

## 三、阶段流程

| 阶段 | 责任角色 | 动作 | 产物 | 验收 |
|------|---------|------|------|------|
| 0 准备 | 各执行 agent | 把自己的数据/凭证存入**本地** MGC | 本地 text 记录 | `mgc_find` 能看到记录 |
| 1 编排 | 编排 agent | 写任务书（模板 1）、准备平级脚本目录 | 任务书 + 脚本目录 | 目录无子目录；脚本无数据文件 |
| 2 存包 | 编排 agent | `mgc_save_file(path="<脚本目录>")` | 脚本入库记录 | `diff_3` 与规格一致 |
| 3 密封 | 编排 agent | 生成 targets（只含 .py）→ `mgc_seal_package` | N 个子包 + `distribution_index.json` | 子包数量 = 数据域数量；sha256 已记录 |
| 4 分发 | 编排 agent | 默认邮件发送 `task_package_NN/`（Subject 含 keyword，sha256 写正文） | 送达确认 | 每个执行方收到且仅收到自己的包 |
| 5 执行 | 各执行 agent | 校验 sha256 → 导入 → 核对授权清单 → 冒烟试跑 → `mgc_run` | 结果摘要 | 授权清单与任务书一致；无 UNSEAL_FAILED |
| 6 回传 | 各执行 agent | 按模板 4 回传（推荐封进 `report.py` 加密） | 回传包 | 不含原始数据 |
| 7 汇总 | 编排 agent | 核对来源指纹 → 导入回传包 → 运行读取 → 汇总 | 最终交付物 | 各域结果齐全 |

## 四、文件授权矩阵

| 文件 | 内部执行 | 外部执行 | 说明 |
|------|:---:|:---:|------|
| `<a.py>` | ✅ | ❌ | 内部域主脚本 |
| `<b.py>` | ❌ | ✅ | 外部域主脚本 |
| `<shared_helper.py>` | ✅ | ✅ | 两域共用（chain mode 跨包共享演示） |
| `<report.py>` | ✅ | ✅ | 结果密封回传（可选） |

> 数据文件与凭证**不出现在本表**——它们不参与打包。

## 五、targets 规格模板

```json
[
  {
    "node_pub": "<内部执行方 PEM>",
    "files": ["<a.py>", "<shared_helper.py>"]
  },
  {
    "node_pub": "<外部执行方 PEM>",
    "files": ["<b.py>", "<shared_helper.py>"]
  }
]
```

## 六、分发与回传

| 环节 | 默认方式 | 备选 |
|------|---------|------|
| 分发 | 邮件附件（`task_package_NN/`） | 共享文件夹 / A2A / HTTPS |
| 回传 | 封进 `report.py` → p2p 密封 → 邮件 | 明文摘要（仅非敏感结果） |

邮件约定（分发与回传通用）：

- Subject 统一使用 `chain:<task_id>`（回传可用 `chain:<task_id>:return`），便于两端按 keyword 轮询过滤。
- 每个附件的 sha256 写在邮件正文，接收方在导入前核验。
- `.mgc_file` 一律作为附件传输，保持后缀不变。

## 七、验收清单

- [ ] 每个子包的 `granted_files` 全部是 `.py`
- [ ] 数据/凭证只存在于各执行方本地 MGC
- [ ] 每个执行方核对过授权清单
- [ ] 每个执行方先冒烟试跑过入口脚本（导入成功 ≠ 可解封，防 UNSEAL_FAILED）
- [ ] 邮件 Subject 含约定 keyword，附件 sha256 与正文一致
- [ ] 回传内容不含原始数据与凭证
- [ ] `distribution_index.json` 的 sha256 与实包一致
- [ ] 编排 agent 全程未接触数据明文

## 八、最小示例（单数据域）

```text
任务：统计本地销售数据并产出摘要
数据域：内部销售数据（1 个）

0 准备：执行 agent 把 sales.csv 存入本地 MGC（owner=local_sales）
1 编排：编排 agent 准备 analyze.py
2 存包：mgc_save_file(path="./pipeline")   # 只有 analyze.py
3 密封：targets = [{"node_pub":"<执行方 PEM>","files":["analyze.py"]}]
4 分发：邮件发送 task_package_01/
5 执行：执行 agent 导入 → 核对清单 → mgc_run("analyze.py")
6 回传：结果摘要 → 封进 report.py → p2p 密封回传
7 汇总：编排 agent 解密汇总
```
