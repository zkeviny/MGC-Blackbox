# ## 单设备多‑Agent 协作技能体系（优化完善版）
### **基于 MGC v1.4.7 的单设备多 Agent 协作方法论**

---

## ### 1. 目标场景  
在单设备环境中部署多个智能体（Agent），或在 OpenClaw 类容器中挂载多个分工明确的子 Agent。  
各 Agent 负责不同业务职能，由主 Agent 接收用户指令、拆解任务链，并协调子 Agent 协作完成完整业务流程。

---

## ### 2. 场景现状（问题背景）  
以“数据分析结果发布”为例：

用户提出分析主题 →  
主 Agent 拆解任务链 →  
子 Agent 分别负责：

- 资料收集  
- 数据采集  
- 数据分析  
- 文稿撰写  
- 图像/视频生成  
- 内容发布  

整个链路会涉及：

- 平台 API 密钥  
- 数据库凭证  
- 敏感业务数据  
- 分析脚本  

**现实问题：**

- 多 Agent 共用同一设备环境  
- 无法对敏感资源做硬隔离  
- 只能依靠提示词软约束  
- 任意 Agent 都可能越权访问密钥或敏感脚本  
- 整个协作链缺乏安全边界  

---

## ### 3. MGC 的工作方法（协作底层机制）  
MGC v1.4.7 提供 **敏感资源执行边界**，足以支撑单设备多 Agent 的协作隔离。

### **MGC 在协作中的角色：敏感资源托管与执行层**

#### ✔ 1. 用户通过 WebUI 存入敏感资源  
包括：

- API 密钥  
- 数据库凭证  
- 数据分析脚本  
- 发布脚本  
- 私有业务逻辑脚本  

这些资源存入 MGC 后：

- 不暴露给任何 Agent  
- 不以明文形式出现  
- 只能通过 mgc_run 执行  

---

#### ✔ 2. 高授信 Agent（脚本角色）负责编写脚本  
由主 Agent指派的脚本角色 Agent：

- 编写数据调用脚本  
- 编写分析脚本  
- 编写发布脚本  
- 使用 `mgc_save` 存入 MGC  
- 告知主 Agent存储位置（info_type / info_owner）

脚本内容对其它 Agent不可见。

---

#### ✔ 3. 主 Agent 负责任务链编排  
主 Agent根据用户目标：

- 拆解任务链  
- 分配子任务  
- 指定哪些步骤需要调用 MGC  
- 告知子 Agent 调用哪个脚本、在什么阶段调用  

主 Agent 是 **协作调度中心**。

---

#### ✔ 4. 执行 Agent 完成非敏感任务  
执行 Agent：

- 完成资料收集、撰稿、生成图像/视频等任务  
- 不接触密钥  
- 不接触敏感脚本  
- 不接触原始数据  
- 需要调用脚本时，只能通过 mgc_run 执行 MGC 内部脚本  

最终实现：

> **多 Agent 协作，但敏感资源永不暴露。**

---

## ### 4. 核心强调（体系定位）  

### ⭐ 单设备多 Agent 协作的核心不是权限管理，而是 **权限分级协作方法论**  
- 敏感资源不分配给 Agent  
- 敏感资源统一托管在 MGC  
- Agent 之间的权限差异由“任务链编排”决定  
- 敏感操作由 MGC 执行  
- 子 Agent 永远不接触敏感资源  

### ⭐ MGC 的未来定位：多 Agent 隐私协作平台  
本体系是 MGC 的第一阶段能力：  
**单设备多 Agent 的隐私协作与敏感资源隔离。**

---

## ### 5. 技能体系搭建（主技能 + 场景技能）

---

# **① 单设备多agent安全协作技能**  
**Multi‑Agent Safe-Cooperation Skill（Single Device）**

### **定位**  
一套完整的协作方法论，说明在单设备多 Agent 场景下，如何通过 MGC 让不同分工的 Agent 协作完成任务，同时避免越权接触密钥与核心脚本。

文档中的技术定位可以使用privacy，但是现在仍处于推广和运营的破局阶段，用safe会更容易获取流量。

---

### **角色分工**

#### **人工（用户）**  
- 存入密钥 / 核心脚本  
- 下达任务目标与阶段性要求  
- 审核关键结果  
- 决定是否自动发布  

---

#### **高授信 Agent（脚本角色）**  
- 按用户提示编写脚本  
- 使用 `mgc_save` 存入 MGC  
- 告知主 Agent脚本位置（info_type / info_owner）  
- 外部脚本需要密钥时，通过 MGC 接口执行  

---

#### **任务编排 Agent（主 Agent）**  
- 分解任务  
- 编排执行顺序  
- 指定脚本调用时机  
- 分配子 Agent 的任务范围  
- 保证敏感操作全部通过 MGC 执行  

---

#### **执行 Agent（子 Agent）**  
- 按任务分工完成非敏感任务  
- 调用脚本时使用 mgc_run  
- 不接触密钥、核心脚本、原始数据  

---

# **② 场景技能 1：数据分析协作链**  
**Data Analysis Collaboration Chain**

### **定位**  
基于主技能，在数据分析场景下构建完整协作链：

- 数据分析任务理解  
- 数据获取（MGC 执行）  
- 数据分析（MGC 执行）  
- 报告撰写  
- 图表生成  
- 结果发布（自动化或人工确认）

---

# **③ 场景技能 2：推文发布协作链**  
**Content Publishing Collaboration Chain**

### **定位**  
基于主技能，在推文发布场景下构建协作链：

- 推文任务理解  
- 信息获取  
- 信息整合  
- 内容生成  
- 多平台发布（MGC 执行 API Key 脚本）

---

# **④ 场景技能 3：营销活动通知协作链**  
**Marketing Notification Collaboration Chain**

### **定位**  
基于主技能，在营销活动场景下构建协作链：

- 活动任务理解  
- 活动目标拆解  
- 数据分析（MGC 执行）  
- 触达任务建立  
- 通知发布（短信/邮件脚本由 MGC 执行）

---
